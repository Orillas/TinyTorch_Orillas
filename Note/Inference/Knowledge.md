### 第一部分：LLM 推理的基本概念与物理瓶颈

LLM 的推理（Inference）是将训练好的模型应用于实际生成任务的过程。现代 LLM（如 GPT、Llama、DeepSeek 等）绝大多数基于 Transformer 的 Decoder-only 架构。其推理过程的核心特征是**自回归（Autoregressive）**，即“基于已有的词，预测下一个词”。

这个过程严格分为两个物理阶段，并且面临着一个核心的资源瓶颈：

#### 1. 两个推理阶段
*   **Prefill 阶段（预填充/首字生成）**：
    *   **动作**：模型一次性读取用户的完整输入（Prompt），并行计算所有 Token 的特征。
    *   **特征**：高度并行化，属于 **计算密集型（Compute-bound）** 任务。GPU 的算力（Tensor Cores）在这个阶段被充分利用。
*   **Decode 阶段（解码/逐字生成）**：
    *   **动作**：模型根据输入和刚刚生成的 Token，按顺序**逐个**预测后续的 Token。新生成的 Token 会被追加到输入序列的末尾，参与下一次预测。
    *   **特征**：严格的串行计算，属于**访存带宽密集型（Memory-bandwidth-bound）**任务。GPU 算力利用率极低，主要时间耗费在将庞大的模型权重和缓存数据从显存搬运到计算单元上。

#### 2. 核心瓶颈：KV Cache（键值缓存）
在 Decode 阶段，为了预测第 $N+1$ 个词，模型本需要重新计算前 $N$ 个词的自注意力（Self-Attention）。为了避免这种极度浪费的重复计算，引入了 **KV Cache** 机制。
*   **原理**：将前 $N$ 个词在各个注意力层中生成的 Key（K）和 Value（V）矩阵保存在显存中。预测时，只需计算当前新词的 Q（Query），并与缓存的 KV 进行点积即可。
*   **代价**：随着序列长度（Context Length）和并发请求数（Batch Size）的增加，KV Cache 的体积会呈线性甚至超线性膨胀，迅速**吃光 GPU 显存**，成为制约推理并发量（Throughput）的绝对瓶颈。

### 第二部分：vLLM 背后的核心理念 —— 显存的“操作系统级”管理

在 vLLM 出现之前（2023年之前），主流推理框架（如 HuggingFace 标准实现）在管理 KV Cache 时采用了**连续显存分配**的静态策略。

*   **痛点**：由于系统无法预知一个请求最终会生成多少个 Token，通常会按照“最大可能长度”（Max Sequence Length）为每个请求预先分配一块连续的显存池。
*   **灾难性后果**：
    1.  **内部碎片**：预分配了 2048 个位置，实际只生成了 10 个词，剩余显存被白白锁定浪费。
    2.  **外部碎片**：由于序列长度长短不一，显存中会出现大量不连续的空隙，无法分配给新的请求。
    *   *加州大学伯克利分校（UC Berkeley）的研究表明，传统方式下，真正存储有效 KV 数据的显存仅占 20%-40%，极度低效。*

**vLLM 的核心理念是：将操作系统（OS）管理系统内存的“虚拟内存与分页机制”引入到 LLM 的显存管理中。**

它的核心技术支柱包含以下三个维度：

#### 核心创新一：PagedAttention（分页注意力）
这是 vLLM 的灵魂。它打破了“同一序列的 KV Cache 必须在物理显存上连续”的限制。

1.  **逻辑与物理分离**：vLLM 将每个序列的 KV Cache 划分为固定大小的“块（Blocks/Pages）”（例如每个 Block 存放 16 个 Token 的 KV 数据）。
2.  **块表映射（Block Table）**：维护一个映射表，将序列中连续的逻辑 Token 映射到不连续的物理显存块上。
3.  **按需分配（On-demand Allocation）**：在 Decode 阶段，模型每生成满一个 Block 的 Token，vLLM 才会向操作系统申请下一个物理块。
4.  **结果**：彻底消除了外部碎片，将内部碎片限制在最后一个未写满的 Block 内（浪费率不到 4%）。这使得同样大小的显存可以同时处理的 Batch Size 提升了 2 到 4 倍，吞吐量实现数量级飞跃。

#### 核心创新二：极致的内存共享与 Copy-on-Write（写时复制）
在实际应用中，很多请求拥有相同的前缀（例如：系统提示词 System Prompt，或者在 Beam Search / Parallel Sampling 树搜索生成时共用同一个问题）。

*   **传统做法**：为每个并发请求单独复制并存储一份 System Prompt 的 KV Cache。
*   **vLLM 做法**：得益于 PagedAttention 的块表机制，不同的序列可以**逻辑映射到同一个物理物理块**上。这意味着复杂的 System Prompt 在物理显存中只存一份，所有请求共享读取。
*   **写时复制（CoW）**：当某一个序列开始生成自己独有的 Token，导致该 Block 的数据需要被修改时，vLLM 才会复制这个物理块（Copy-on-Write），确保各个序列的独立性。这极大地降低了复杂解码策略下的显存占用。

#### 核心配套机制：Continuous Batching（持续批处理 / 动态批处理）
结合了高效的 PagedAttention，vLLM 完美契合了持续批处理的调度逻辑。
*   传统批处理（Static Batching）必须等待 Batch 中最长的序列生成完毕，才能整体退出，期间较短的序列即使早早生成结束，也要占据显存“陪跑”。
*   **Continuous Batching**：以迭代（Iteration）而非请求（Request）为调度单位。只要 Batch 中有序列生成结束（遇到了 EOS Token），立即将其移出，并瞬间把等待队列中的新请求插入到 Batch 中进行 Prefill。系统利用率始终保持在饱和状态。

### 总结

概括而言，LLM 推理的本质是在**有限的显存容量和访存带宽下，最大化 Token 的吞吐率**。

**vLLM 并非在模型数学结构上做文章，而是从底层计算机系统的工程学角度，用“分页内存管理”的思想降维打击了传统的“静态显存分配”。** 通过 PagedAttention、Copy-on-Write 和 Continuous Batching 的组合拳，vLLM 将显存利用率从不足 40% 逼近至 90% 以上，从根本上定义了现代高性能大模型推理引擎的基础标准。
